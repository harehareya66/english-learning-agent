# 产品开发方案（多端触达 + 大词库）

> 依据《智能体接入产品 · 落地方案报告》「后续演进方向」七项规划拆解。
> 优先级：P0（地基）→ P1（核心扩展）→ P2（体验增强）。

## 一、演进目标与定位

把产品从「桌面 Web 原型」推进为「手机端 + 微信小程序 + Web 三端可用、词库千级、随时随学」的智能英语学习产品。

核心原则不变：**能本地解决的不调模型**，高频确定能力（查词 / 复习 / 测评 / 错题 / 口语）保持 0 token 本地运行，AI 仅作兜底对话与个性化讲解。

## 二、演进方向 → 功能清单

| 演进方向 | 落地功能 | 优先级 |
|---------|---------|--------|
| 手机端（移动端）适配 | H5 响应式布局 + 底部 Tab 导航 + 触控交互优化 + PWA 离线缓存 | P0 |
| 云端部署 + 数据同步 | 账号体系 + 学习数据云同步（多端闭环的前提） | P0 |
| 微信小程序 | 核心学习链路小程序化 + 微信登录 + 小程序录音发音评测 | P1 |
| 词库扩充（更多词库） | 四六级 / 考研 / 雅思 / 托福 / 职场分场景词库 + 多词库切换，规模 30 → 千级 | P1 |
| 背词题型扩展 | 看词选义（4 选 1）+ 拼写题 + 听音选词 | P2 |
| 发音评测 | 录音 → ASR → 发音评分反馈 | P2 |
| 每日目标可配置 | 自定义目标词数，打卡进度联动 | P2 |

## 三、分阶段开发路线

### Phase 0 · 工程地基：多端复用 + 数据同步打底
这是所有后续阶段的前提，先把「一套逻辑多端复用」和「跨端数据一致」的地基打好。

1. 抽象共享服务层：把词库查询、艾宾浩斯调度、测评题生成、意图分流从 Express 路由中抽成纯函数模块，供 Web / 小程序共用。
2. 词库 Schema 标准化：单词字段扩展为 拼写 / 音标 / 释义 / 词根 / 词族 / 例句 / 词频 / 所属词库。
3. 账号体系：引入用户表与登录态，学习进度、记忆库、错题本挂到用户维度。
4. 后端 API 化：现有路由收敛为 RESTful API，供多端调用。

### Phase 1 · 手机端适配（H5 + PWA）
1. 布局重构：桌面侧边栏 → 移动端底部 TabBar，七大功能入口自适应。
2. 响应式断点：CSS media query + Tailwind 断点，卡片自适应竖屏。
3. 触控交互：卡片左右滑动翻词、按钮热区不小于 44px、TTS 发音。
4. PWA：Service Worker 离线缓存 + manifest，支持「添加到主屏幕」。

### Phase 2 · 微信小程序
1. 技术选型：Taro（React 语法）复用现有组件与共享模块，降低双端维护成本。
2. 登录：wx.login → openid 绑定账号体系，打通云同步。
3. 后端：Express 部署云上提供 HTTPS API；小程序录音 → 云 ASR 实现发音评测。
4. 交付：微信内即开即用，触达微信生态用户。

### Phase 3 · 词库扩充
1. 数据来源：开源词库（ECDICT / COCA 词频表 / 四六级·考研大纲词汇）。
2. 处理 Pipeline：采集 → 清洗去重 → 词根词缀标注 → 词族归类 → 音标例句补齐 → 入库。
3. 分场景建库：四六级 / 考研 / 雅思 / 托福 / 职场高频，支持多词库切换与组合学习。
4. 交付：千级、多场景词库，覆盖主要备考与职场场景。

### Phase 4 · 学习能力增强
1. 题型扩展：看词选义（4 选 1）、拼写题、听音选词，干扰项由本地同词族 / 近义词生成。
2. 发音评测：Web MediaRecorder / 小程序 recorder 录音 → ASR 服务 → 发音评分反馈。
3. 每日目标可配置：目标词数自定义，首页打卡进度按目标动态计算。

### Phase 5 · 云端部署 + 数据同步
1. 部署 Node 云平台，SQLite 持久化磁盘（或按需迁移 PostgreSQL）。
2. 跨端数据同步：学习进度、记忆库、错题本在 Web / 手机 / 小程序间实时一致。
3. 交付：任意设备、随时继续学习，形成公网可访问的正式产品。

## 四、功能实现方式要点

| 功能 | 关键技术 | 依赖 |
|------|---------|------|
| 响应式适配 | CSS media query + Tailwind 断点 + 底部 TabBar 组件 | 无，前端改造 |
| PWA 离线 | Service Worker + manifest | 无 |
| 微信小程序 | Taro（React 语法）复用组件；wx.login 登录 | 小程序后端 HTTPS |
| 词库扩充 | 开源词库 + 词根标注 Pipeline | 数据采集 / 清洗 |
| 选择题型 | 本地干扰项生成（同词族 / 近义词） | 无，本地实现 |
| 发音评测 | 录音 → ASR（讯飞 / 腾讯云 / 微信同传） | 外部 ASR API |
| 每日目标 | 设置存储 + 打卡进度计算 | 本地 / 云端 |
| 云同步 | 账号体系 + 学习数据同步 | 云端数据库 |

## 五、用户使用闭环分析

**结论：能形成闭环，且升级为「跨端连续闭环」。** 原有单端闭环完整，多端 + 云同步后，用户可在不同设备间无缝衔接学习，闭环从「单设备」升级为「随时随处」。

- **单端闭环（现状，已验证）**：学词 → 记忆库 → 到期复习（艾宾浩斯）→ 自评 → 测评检验 → 错题归档 → 错题回流复习 → 掌握 → 打卡。
- **跨端闭环（演进后）**：手机背词 → 小程序复习 → Web 测评 → 云同步一致 → 任意设备继续。
- **关键前提与风险**：账号体系 + 云同步必须先落地；发音评测依赖外部 ASR；词根标注质量是壁垒；跨端以云端为准。

## 六、工作流程

**开发流程**：需求拆解 → 数据层抽象 → 共享服务模块 → 各端 UI → 联调 → 测试 → 灰度 → 发布。

**产品使用流程**：选词库 → 定目标 → 每日背词 → 复习 → 测评 → 打卡 → 跨端继续。

## 七、优化建议

| 类别 | 建议 | 要点 |
|------|------|------|
| 分期优先级 | 先 P0（账号 + 云同步 + 手机端），再 P1（小程序 + 词库），最后 P2 | 地基优先 |
| 成本控制 | 本地能力 0 token；AI 可选；发音评测按需计费 | 0 token 兜底 |
| 风险对策 | ASR 可降级；词库核对版权；跨端以云端为准 | 可降级 |
| 技术债 | 先抽象共享层再开发，避免三端逻辑分叉 | 共享优先 |

**总体建议**：按 Phase 0 → 1 → 2 → 3 → 4 → 5 顺序推进，每阶段均形成可体验、可验证的交付物。
