# 产品开发任务清单

> 依据飞书《产品开发方案（多端触达 + 大词库）》拆解，按 Phase 顺序执行。
> 优先级：P0（地基）→ P1（核心扩展）→ P2（体验增强）。每阶段均形成可体验、可验证的交付物。

## Phase 0 · 工程地基（P0，先做）

| # | 任务 | 交付物 | 验收标准 |
|---|------|--------|----------|
| 0.1 | 抽象共享服务层 | `shared/` 纯函数模块（意图分类 / 艾宾浩斯 / 测评题生成） | 纯函数无 DB 依赖，可被 Web 与小程序共同 import |
| 0.2 | 词库 Schema 标准化 | `words` 表扩展 book_id / frequency / example 字段 | 词库可分库、可按词频排序、含例句 |
| 0.3 | 账号体系 | `users` 表 + `user_id` 挂到 word_memory / mistakes | 学习进度、错题本按用户隔离 |
| 0.4 | 后端 API 化 | 路由收敛为 RESTful，多端可调用 | 同一套 API 供 Web / 小程序使用 |

## Phase 1 · 手机端适配（P0）

| # | 任务 | 交付物 | 验收标准 |
|---|------|--------|----------|
| 1.1 | 响应式布局 | 侧边栏 → 底部 TabBar | 手机竖屏 7 大功能入口可完整操作 |
| 1.2 | 触控交互 | 卡片滑动翻词、按钮热区 ≥44px、TTS 发音 | 手机上操作流畅、不误触 |
| 1.3 | PWA 离线 | Service Worker + manifest | 可添加到主屏幕，弱网可开 |

## Phase 2 · 微信小程序（P1）

| # | 任务 | 交付物 | 验收标准 |
|---|------|--------|----------|
| 2.1 | Taro 工程初始化 | 复用 shared 模块的小程序工程 | 复用同一套业务逻辑，零逻辑分叉 |
| 2.2 | 登录打通 | wx.login → openid 绑定账号 | 微信身份与账号体系打通、数据同步 |
| 2.3 | 核心页面小程序化 | 背词 / 复习 / 测评三个页面 | 微信内即开即用，可完成一轮学习闭环 |

## Phase 3 · 词库扩充（P1）

| # | 任务 | 交付物 | 验收标准 |
|---|------|--------|----------|
| 3.1 | 数据源接入 | ECDICT / COCA 词频 / 四六级·考研大纲词 | 千级规模、多来源去重 |
| 3.2 | 词根标注 Pipeline | 词根词缀标注 + 词族归类脚本 | 标注准确、词族归类正确 |
| 3.3 | 分场景建库 | 四六级/考研/雅思/托福/职场词库 | 支持多词库切换与组合学习 |

## Phase 4 · 学习能力增强（P2）

| # | 任务 | 交付物 | 验收标准 |
|---|------|--------|----------|
| 4.1 | 题型扩展 | 看词选义(4选1) / 拼写题 / 听音选词 | 干扰项合理、判分正确 |
| 4.2 | 发音评测 | 录音 → ASR → 发音评分 | 可录音、返回评分与反馈 |
| 4.3 | 每日目标可配置 | 目标词数自定义 | 打卡进度按目标动态计算 |

## Phase 5 · 云端部署（P2）

| # | 任务 | 交付物 | 验收标准 |
|---|------|--------|----------|
| 5.1 | 云平台部署 | Node 云平台运行实例 | 公网可访问、功能完整 |
| 5.2 | 跨端数据同步 | 三端数据一致 | 手机 / 小程序 / Web 进度实时同步 |

## 关键前提提醒

- **账号体系 + 云同步（0.3）是跨端闭环的硬前提**，必须先于 Phase 1/2 的多端开发落地。
- 本地能力保持 0 token；AI 对话可选；发音评测按需计费。
- 风险点：ASR 依赖（可降级）、词库版权（需核对）、跨端一致性（以云端为准）。
