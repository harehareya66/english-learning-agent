# 可用性测试优化清单（2026-08-15）

> 用自研 CDP 脚本（web-usability-tool）遍历 8 个页面测试，**8 页全部 0 JS 报错、0 网络失败**，底层稳定。以下为发现的体验/性能/内容问题。

## 🔴 高优先级（体验与正确性）

### 1. 首页「待背 989 词」文案误导 + 背单词新词数硬编码
- **现象**：首页显示「开始背单词（今日 0/20 · 待背 989 词）」，但进入背单词页实际只有 **10 个新词** + 到期词。
- **根因**：
  - 首页 `newWordsCount = totalWords - learnedCount` = 989（**未学词总数**）
  - 背单词接口 `/api/recite/queue` 新词 `slice(0, 10)`（**硬编码 10**，未对齐每日目标）
- **影响**：用户以为要背 989 个词，实际只能背 10 个，数量对不上、挫败预期。
- **优化建议**：背单词新词数对齐「每日目标 - 今日已背」（如目标 20 词则每次补足 20）；首页文案改为「本轮可背 N 词」而非未学词总数。

### 2. 单词库性能：1022 词一次性渲染（997 个按钮）
- **现象**：单词库页 28362 字正文、997 个按钮，1022 个词卡片全展开渲染。
- **影响**：DOM 节点过万，移动端滚动卡顿、首屏加载慢。
- **优化建议**：词族默认**折叠**（只显示词族名 + 成员数，点开才显示成员）；进一步可上虚拟滚动/分页。

## 🟡 中优先级（内容质量）

### 3. 单词库「其他」组过大（644 词）
- **现象**：644 个无词根基础词全部归入「其他 · 词族 644 词」，单组过大难以浏览。
- **优化建议**：①「其他」组按字母首字母（A-Z）或语义分类细分；② 复用词根标注 pipeline 提升覆盖率（当前 35%）。

## 🟢 低优先级（UI 细节）

### 4. 设置页标题重复
- **现象**：Header 显示「设置」+ 页面内 h1 也是「设置」，同屏重复。
- **优化建议**：去掉页面内 h1 或 Header 标题之一。

### 5. 口语页场景标题/tag 重复
- **现象**：场景卡片「At the Airport 机场值机」下又显示 tag「机场出行」，信息冗余。
- **优化建议**：合并为一行，或 tag 改为难度/词数等更有信息量的标签。

### 6. 背单词题型随机可预测性
- **现象**：每次进入背单词页题型随机分配，同一词题型可能变化（脚本交互测试「播放发音」因题型随机 NOT_FOUND）。
- **优化建议**：可在顶部显示「本轮共 X 题：选义/拼写/听音/发音」，或改为固定轮换顺序（对用户更有节奏感）。

## 🔍 第二轮：用户视角发现的 4 个问题

> 第一轮做完后再走完整流程，以「学英语用户」视角发现的新问题（开发者看不到的数字对不上/混排等体验问题）

| # | 严重度 | 问题 | 修复 |
|---|--------|------|------|
| A | 🔴 | **背单词第一个词是 ambiguous**（9 字母六级难词）—— getAllWords 按 word ASC 字母序，新词排序不合理，用户第一次背单词就撞生僻词 | recite/queue 新词 `sort by frequency 降序`，前 5 变 passage/question/people/well/answer（高频简单词） |
| B | 🔴 | **首页「学习中 9 · 已掌握 0 / 已学 33」数字对不上** —— 33 = 刚学 24 + 学习中 9 + 已掌握 0，但「刚学」没显示 | 补充「刚学 {fresh} · 学习中 {learning} · 已掌握 {mastered} / 已学 33」 |
| C | 🟡 | **单词库字母组/词根组混排** —— A-Z 字母组（无词根）和词根组（norm/surd/cap）混在一起，用户分不清为什么有的按字母、有的按词根 | 拆为「词根词族 · 词根记忆法」+「基础词 · 按字母」两个区块（带分隔标题） |
| D | 🟢 | **AI 对话历史残留**（"用英语和我聊聊今天的天气"等测试会话） | 清 sessions+messages 归零 |

**关键反思**：开发者视角看不到「数字对不上」「字母组/词根组混排」「第一个词是难词」这种用户感知的体验问题，必须假设用户视角才能发现。
