## 一、数据类决策

### 1. 是否现在清空测试数据？
- **现状**：30 个词已全部标记为「已学」，是新用户体验到「空壳背单词页」的根因。
- **选项**：
  - A.（建议）现在就点一次「重置学习进度」清空，让我以「全新用户」视角重新完整走一遍闭环。
  - B. 保留现有数据（你已验收过），不做清空。
- **影响**：选 A 后我可以验证「学新词 → 复习 → 测评」的完整首轮体验。

### 2. 掌握度口径是否认可？
- **现状**：我已把「已掌握 0/已学 30 · 0%」改成「学习中 9 · 已掌握 0 / 已学 30」，进度条按「脱离 L0 的单词占比」计算。
- **选项**：
  - A.（建议）认可当前「学习中/已掌握」两段式。
  - B. 想要更严格的「纯掌握百分比」（L4+L5 占比）。
  - C. 想要更细的分级展示（L0-L5 每个等级的数量条）。
- **影响**：决定用户看到的是「成就感」还是「距离感」。

## 二、路线类决策（Phase 2-5）

### 3. 微信小程序技术栈（Phase 2）
- **选项**：
  - A.（建议）**Taro**（React 语法，最大程度复用现有 React 组件与 shared 逻辑）。
  - B. **uni-app**（Vue 语法，需重写组件）。
  - C. **原生小程序**（性能最好，开发量最大）。
- **影响**：决定 Phase 2 的工期与代码复用率。
- **前置**：需要你有一个**微信小程序 AppID**（个人/企业均可），没有的话我可以先搭框架、后补 AppID。

### 4. 词库数据来源与版权（Phase 3）
- **现状**：当前 30 词是手写种子数据。
- **选项**：
  - A.（建议）用开源词库（ECDICT、COCA 词频表、四六级/考研大纲）做采集 + 词根标注，注意核对来源的授权。
  - B. 只用「大纲词汇」这类无版权争议的官方列表，词根标注自己补。
  - C. 购买/接入第三方商用词库 API。
- **影响**：决定词库规模（千级）与合规风险。

### 5. 发音评测 ASR 供应商（Phase 4）
- **选项**：
  - A.（建议）腾讯云/讯飞 ASR（国内稳定、有免费额度、支持发音评分）。
  - B. 微信同声传译（小程序内免费，但仅小程序端可用）。
  - C. 暂不做发音评测（去掉 Phase 4 的 ASR 项）。
- **影响**：涉及 API 成本与账号开通；选 C 可简化 Phase 4。

### 6. 部署最终方案（Phase 5）
- **现状**：之前折腾过 Render（要绑卡）、Railway（前30天免费）、内网穿透（依赖本机在线）。
- **选项**：
  - A.（建议）**Railway**（连 GitHub，前 30 天免费、不休眠，之后月费很低）。
  - B. **腾讯云/阿里云轻量服务器**（长期稳定可控，需你自己有账号）。
  - C. 暂不部署，先用本地 + 内网穿透演示。
- **影响**：决定产品能否「公网随时可访问」。
